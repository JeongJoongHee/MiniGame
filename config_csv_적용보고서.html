1. 검토 결과 — 됩니다

이제 난이도 수치는 전부 config.csv 한 파일에서 나옵니다. 엑셀로 열어서 고치고 저장하면 다음 Play 부터 바로 반영됩니다. Unity 를 다시 켤 필요도, 저한테 부탁하실 필요도 없습니다.

고치실 파일

D:\00.JumpJump\config.csv

지금 두신 그 자리 그대로입니다. 게임은 프로젝트 안쪽의 사본 (JumpJump\Assets\JumpJump\config.csv)을 읽는데, 바깥 파일이 더 새로우면 씬을 굽거나 테스트를 돌릴 때 자동으로 복사됩니다. 두 파일을 따로 관리하실 필요 없습니다.

값이 어떻게 읽혔는지 확인하려면

Unity 메뉴 Tools > JumpJump > Apply config.csv 를 누르면 Console 에 지금 적용된 표가 그대로 찍힙니다. 오타나 이상한 값이 있으면 몇 번째 줄인지 알려 줍니다.

2. 빠진 열이 있어서 두 개 채웠습니다

주신 config.csv 에는 Timer 와 Base_Speed 는 있었지만 발판 최소/최대 열이 없었습니다. 지난번 수정사항_01 에서 정하신 값이라 그냥 버리면 안 될 것 같아, 높이를 맞춰서 그대로 옮겨 담고 열 두 개를 추가했습니다.

1001m 위쪽은 수정사항_01 에 없던 구간이라(그때는 1000m 이상이 마지막이었습니다) 마지막 값인 1칸을 이어서 넣었습니다. 바꾸고 싶으시면 그 열만 고치시면 됩니다.

머리글의 오타(Heght_Min, Heigh_Max)는 바른 철자로 고쳤습니다. 다만 파서가 오타 쪽도 알아듣게 해 뒀으니, 나중에 엑셀에서 다시 내보내셔도 그대로 동작합니다.

3. 열 설명

열뜻게임이 읽나?
Index구간 번호안 읽음 (보기 편하라고)
Height_Min구간 시작 높이(m)안 읽음 (참고용)
Height_Max구간의 높이 상한(m)읽음 — 구간을 나누는 기준
Timer새 칸을 밟았을 때 초기화되는 타이머(초)읽음
Base_Speed발판이 좌우로 움직이는 속도읽음
Blocks_Min / Blocks_Max발판 블록 수. 칸마다 이 사이에서 무작위읽음

Index 와 Height_Min 을 읽지 않는 이유는, 구간이 위에서부터 순서대로 Height_Max 로만 갈리기 때문입니다. 1번 줄이 0~100m, 2번 줄이 100~200m 을 맡는 식이고 맨 마지막 줄이 그 위 높이 전부를 담당합니다. 그래도 표를 볼 때 필요한 열이라 그대로 두었습니다.

4. 이런 것도 됩니다

나중에 표를 손보실 때 걸리지 않도록, 파일을 웬만큼 험하게 다뤄도 견디게 만들었습니다.

  • 열 순서를 바꿔도 됩니다. 위치가 아니라 이름으로 찾습니다.
  • 메모용 열을 추가해도 됩니다. 모르는 열은 그냥 무시합니다. (예: 비고 열에 "여기부터 어려움" 같은 메모)
  • 줄을 늘리거나 줄여도 됩니다. 16구간을 30구간으로 쪼개도 그대로 동작합니다.
  • 이름은 대소문자·공백·밑줄을 무시하고 비교합니다. Height_Max, heightMax, 높이 가 전부 같은 열입니다.
  • # 로 시작하는 줄은 주석으로 건너뜁니다.
  • 엑셀이 저장하는 한글 인코딩(BOM)·줄바꿈·따옴표를 전부 처리합니다.
  • 값이 이상하면(최소 > 최대, 높이가 거꾸로) 몇 번째 줄인지 Console 에 경고가 뜨고, 게임은 멈추지 않고 알아서 고쳐서 굴러갑니다.
  • CSV 를 아예 못 읽으면 GameConfig 에 구워 둔 값으로 대신 굴러갑니다. 파일 하나 잘못 건드렸다고 게임이 안 켜지는 일은 없습니다.

자동 반영 실제 테스트

7. 난이도가 눈에 띄게 좋아졌습니다

사망 원인이 바뀌었습니다 — 좋은 신호입니다.

봇으로 15분치를 돌려 같은 조건에서 비교했습니다.

수정사항_01config.csv (지금)
봇 최고 도달148칸 (326m)462칸 (1019m)
사망 원인7판 전부 TIME OVER3판 전부 FELL DOWN
최고 점수42,500136,700

전에는 시간이 모자라서 죽었습니다. 발판이 좁아지고 빨라지는 게 의미가 없었고, 그냥 빨리 못 올라가면 끝이었습니다. 지금은 발판을 놓쳐서 죽습니다. 타이머를 5초→7초로 여유 있게 주고 속도를 1~2에서 1~12로 크게 벌리신 게 정확히 맞아떨어졌습니다. 이게 이 장르에서 원하는 모양입니다 — 못해서 죽는 거지 느려서 죽는 게 아니니까요.

참고할 숫자 하나

한 번 점프해서 다음 칸에 내려앉는 데 약 0.5초가 걸립니다. 속도 12인 최상단 구간에서는 그 0.5초 동안 발판이 6칸(월드 6유닛)을 이동합니다. 플레이 가능한 폭이 8유닛이니, 한 번 뛰는 사이에 발판이 화면을 거의 가로지릅니다. 아주 빡빡하지만 봇도 1019m 까지 올라갔으니 불가능한 수준은 아닙니다. 직접 해 보시고 감을 잡으신 뒤 CSV 에서 조절하시면 됩니다.
