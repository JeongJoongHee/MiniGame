# JumpJump (점프점프!) — 미니게임 1번

기획서(`@기획서.docx`)와 스케치(`@메인 화면.png`)를 그대로 구현한 세로형 하이퍼캐주얼 점프 게임입니다.

이 게임은 **미니게임 모음 앱 "심심할 때 하는 게임" 안의 첫 번째 게임**입니다.
타이틀 / 로비(게임 선택) 껍데기는 `Assets/Shell/` 에 따로 있습니다.
앱 전체 흐름과 미니게임 추가 방법은 **`Assets/Shell/README.md`** 를 보세요.

## 실행 방법

1. Unity 에디터에서 프로젝트를 엽니다. (Unity 6000.0.81f1)
2. 상단 메뉴 **Tools > Arcade > Build All Scenes** 를 누릅니다.
   - 타이틀 / 로비 / 게임 씬 3장이 통째로 만들어지고 Build Settings 도 정리됩니다.
   - 픽셀아트 임포트 설정(PPU / 피벗 / Point 필터)도 이때 자동으로 잡힙니다.
   - 마지막에 TitleScene 이 열리므로 Play 를 누르면 앱 처음부터 돕니다.
3. 이 게임만 따로 보고 싶으면 **Tools > JumpJump > Build Game Scene** 으로
   `Assets/JumpJump/Scenes/GameScene.unity` 만 굽고 Play 하면 됩니다.

마우스 클릭 / 터치 / 스페이스바로 점프합니다.
화면 오른쪽 맨 위에는 **뒤로가기 화살표**가 항상 떠 있습니다. 누르면
"로비로 나가시겠습니까?" 팝업이 뜨고, 확인하면 로비로 돌아갑니다 (진행 상황은 저장 안 함).
버튼과 팝업은 껍데기가 만듭니다 — `Assets/Shell/README.md` 의 "나가기 / 설정 팝업" 절 참고.

## 조작

| 입력 | 동작 |
| --- | --- |
| 화면 터치 / 마우스 좌클릭 / 스페이스 | 점프 (수직) |

캐릭터는 공중에서 좌우로 움직이지 않습니다. 발판이 좌우로 움직이므로,
**위 칸 발판이 내 머리 위로 오는 타이밍**에 눌러야 올라갑니다.
착지하면 그 발판을 타고 함께 좌우로 이동합니다.

한 판을 시작할 때마다 `Art/Characters/` 의 캐릭터 5종 중 하나가 무작위로 뽑힙니다.

## 확정된 규칙

기획서에 "정해야 한다"고 남아 있던 부분을 다음과 같이 정했습니다.

| 항목 | 규칙 |
| --- | --- |
| 타이머 | 초당 1씩 감소. **새로운 칸을 밟으면 그 구간의 값으로 초기화** (더해 주는 게 아니라 꽉 채웁니다). 0이 되면 게임 오버. 구간별 값은 `config.csv` |
| 점수 | **도달 높이 기준 + 콤보 배수**. 새 칸을 밟을 때 `100 x 배수` 획득, 배수 = `1 + 콤보 x 0.1` (최대 3배). 이미 올라간 칸을 다시 밟으면 점수 없음 |
| 콤보 | 새 칸을 밟을 때마다 +1, 같은 칸이나 아래 칸에 떨어지면 0으로 초기화 |
| 낙하 | 카메라는 위로만 따라 올라갑니다. **화면 아래로 벗어나면 즉시 게임 오버** (약 2칸 아래) |
| 난이도 | 높이 100m 단위 구간표(`config.csv`)로 발판 폭 / 타이머 / 이동 속도가 한꺼번에 바뀝니다 |
| 높이 | 1 월드 유닛 = 1m, 한 칸 = 2.2m |

## 난이도 구간표 — `config.csv`

**난이도 수치는 전부 `config.csv` 한 파일에 있습니다.** 엑셀로 열어 고치고 저장하면
다음 Play 부터 바로 반영됩니다. Unity 를 다시 켤 필요도, 코드를 볼 필요도 없습니다.

파일은 두 군데에 있고 내용은 같습니다.

| 위치 | 용도 |
| --- | --- |
| `D:\00.JumpJump\config.csv` | **여기를 고치세요.** 작업 폴더에 있어 찾기 쉽습니다 |
| `JumpJump/Assets/JumpJump/config.csv` | 게임이 실제로 읽는 사본. 아래 메뉴가 자동으로 맞춰 줍니다 |

바깥 파일이 더 새로우면 **Build Game Scene / Playtest / Capture Preview** 를 실행할 때
자동으로 안쪽에 복사됩니다. 지금 값이 어떻게 읽혔는지 확인만 하고 싶으면
**Tools > JumpJump > Apply config.csv** 를 누르세요. Console 에 표가 찍힙니다.

### 열 설명

| 열 | 뜻 |
| --- | --- |
| `Index` | 구간 번호. 읽지 않습니다. 사람이 보기 편하라고 있는 열입니다 |
| `Height_Min` | 구간 시작 높이(m). 이 열도 읽지 않습니다 — 참고용입니다 |
| `Height_Max` | **구간의 높이 상한(m).** 실제로 구간을 나누는 기준입니다 |
| `Timer` | 이 구간에서 새 칸을 밟았을 때 초기화되는 타이머(초) |
| `Base_Speed` | 발판이 좌우로 움직이는 속도 |
| `Blocks_Min` / `Blocks_Max` | 발판 블록 수. 칸마다 이 사이에서 **무작위**로 뽑습니다 |

읽지 않는 열이 있는 이유는, 구간이 **위에서부터 순서대로** `Height_Max` 로만
갈리기 때문입니다. 1번 구간이 0~100m, 2번이 100~200m 을 담당하는 식이고
**맨 마지막 줄이 그 위 높이 전부**를 맡습니다.

### 이런 것도 됩니다

- **열 순서를 바꿔도** 됩니다. 위치가 아니라 이름으로 찾습니다.
- **메모용 열을 추가해도** 됩니다. 모르는 열은 그냥 무시합니다.
- 이름은 대소문자·공백·밑줄을 무시하고 비교합니다. `Height_Max`, `heightMax`,
  `높이` 가 전부 같은 열로 인식됩니다. (원본의 오타 `Heigh_Max` 도 인식합니다)
- **줄을 늘리거나 줄여도** 됩니다. 20구간으로 쪼개도 그대로 동작합니다.
- `#` 로 시작하는 줄은 주석으로 건너뜁니다.
- 값이 이상하면(최소 > 최대, 높이가 거꾸로) Console 에 어느 줄인지 경고가 뜹니다.
  게임은 멈추지 않고 고쳐서 굴러갑니다.

### 현재 값

한 칸 = `rowSpacing` = 2.2m 이므로 100m 는 약 45칸입니다.

| ~500m | 182~227 | 2~4 | 5초 | 3.0 |
| ~600m | 228~272 | 2~3 | 5초 | 3.5 |
| ~700m | 273~318 | 1~3 | 4초 | 4.0 |
| ~800m | 319~363 | 1~3 | 4초 | 4.5 |
| ~900m | 364~409 | 1~2 | 4초 | 5.0 |
| ~1000m | 410~454 | 1~2 | 3초 | 6.0 |
| ~1100m | 455~500 | 1 | 2초 | 7.0 |

  (CSV 를 연결하지 않으면 이 목록이 그대로 쓰입니다)

## 튜닝

**모든 수치는 `Assets/JumpJump/GameConfig.asset` 인스펙터에 모여 있습니다.** 코드를 고칠 필요가 없습니다.

자주 만질 값:

- `jumpApex` — 점프 최고점. **반드시 `rowSpacing` 보다 커야** 한 칸 위로 올라갈 수 있습니다. (현재 3.0 vs 2.2)
- `gravity` — 클수록 점프가 짧고 빠릿해집니다.
- 난이도(발판 폭 / 타이머 / 이동 속도)는 `GameConfig` 가 아니라 **`config.csv`** 에 있습니다.
  위 "난이도 구간표" 절을 보세요.
- `landPad` — 발판 끝에서 착지를 얼마나 봐줄지.

값을 바꾼 뒤 **Tools > JumpJump > Run Headless Playtest** 를 실행하면
플레이 모드에 들어가지 않고 120초 분량을 시뮬레이션해서
"봇이 몇 칸까지 오를 수 있는지"를 Console 에 찍어 줍니다. 난이도 확인용입니다.

## 아트 파이프라인

`Tools > JumpJump > Setup Art Assets` 가 각 PNG 의 **실제 내용 영역(알파 바운딩 박스)** 을 재서
PPU 와 피벗을 자동 계산합니다. 그림마다 여백이 달라도 알아서 맞습니다.

| 리소스 | 처리 |
| --- | --- |
| 캐릭터 5종 | 내용 높이가 모두 `playerSize.y` 가 되도록 PPU 를 개별 계산 -> 5종의 키가 통일됨. 피벗은 **발바닥**에 찍어 발판 위에 정확히 서고, 스쿼시도 발 기준으로 걸림 |
| `Base.png` | 내용 가로폭이 `blockWidth` 가 되도록 PPU 계산. 세로 비율에서 `GameConfig.blockHeight` 를 역산해 에셋에 기록 -> 타일이 찌그러지지 않음 |
| `Background/BG_*.png` | Tiled 드로우 모드에 필요한 Full Rect 메시로 설정. **폴더를 통째로 훑으므로 파일을 추가하면 자동으로 잡힙니다** (파일 이름 순서 = 낮은 구간 -> 높은 구간) |

공통으로 **Filter Mode = Point / Compression = None / Mipmap 끔** 이 적용됩니다.

한 번 설정된 텍스처는 `userData` 표시로 건너뛰므로, 그림을 교체한 뒤에는
메뉴를 직접 실행해 다시 재도록 하세요.

## 캐릭터 모션

캐릭터 PNG 가 **1프레임짜리라 애니메이션 클립이 없습니다.** 대신 `CharacterAnimator` 가
코드로 움직임을 만듭니다.

- 점프 순간 세로로 늘어남 (`jumpStretch`)
- 상승/하강 속도에 비례해 계속 늘어남 (`squashStrength`, 부피 유지라 늘어나면 홀쭉해짐)
- 착지 순간 납작하게 눌렸다가 튀어오름 (`landSquash`, `squashRecovery`)
- 발판 위 대기 중 숨쉬기 바운스 (`idleBobAmount`, `idleBobSpeed`)
- 발판이 흐르는 방향으로 좌우 반전 (`SpriteRenderer.flipX`)

나중에 진짜 프레임(걷기/점프 시트)이 생기면 `CharacterAnimator` 에 프레임 배열과
타이머만 추가하면 됩니다. 나머지 코드는 건드릴 필요 없습니다.

## 설계 메모

- **물리 엔진을 쓰지 않습니다.** Rigidbody2D / Collider2D 없이 직접 적분하고,
  착지는 "이번 프레임에 발이 발판 윗면을 아래로 통과했는가"를 수식으로 판정합니다.
  프레임률과 무관하게 결과가 같고, 빠른 낙하에서 발판을 뚫는 문제가 없습니다.
- **아래에서 위로는 발판을 통과합니다.** 하강 중(`vy <= 0`)에만 착지 판정을 합니다.
- `GameManager.Step(dt, tap)` 이 입력과 델타타임을 인자로 받기 때문에
  자동 플레이테스트가 실제 게임 코드를 그대로 재생할 수 있습니다.

## 아트 교체

`Assets/JumpJump/Art/` 아래 PNG 를 같은 이름으로 덮어쓴 뒤
**Tools > JumpJump > Setup Art Assets** 를 실행하면 PPU/피벗이 다시 계산됩니다.
캐릭터를 6종 이상으로 늘리려면 `Art/Characters/` 에 파일을 추가하고
**Build Game Scene** 을 다시 실행하면 자동으로 목록에 들어갑니다.

## 안드로이드 APK 만들기

**Tools > JumpJump > Build Android APK** 하나면 끝입니다.
Build Settings 창을 열 필요도, 플랫폼을 손으로 바꿀 필요도 없습니다.

결과물은 작업 폴더에 `JumpJump.apk` 로 떨어집니다.

| 항목 | 값 |
| --- | --- |
| 패키지 이름 | `com.zkfpf.jumpjump` |
| CPU | ARM64 (IL2CPP) |
| 화면 | 세로 고정 |
| 서명 | Unity 디버그 키 |

**디버그 키로 서명되므로 기기에 직접 설치(사이드로드)하는 용도입니다.**
플레이스토어에 올리려면 따로 keystore 를 만들어 서명해야 하고, 형식도
APK 가 아니라 AAB 여야 합니다. 그때가 되면 `JumpJumpBuild.cs` 의
`useCustomKeystore` 와 `buildAppBundle` 을 바꾸면 됩니다.

기기에 넣는 방법은 파일을 폰으로 옮긴 뒤 탭해서 설치하면 되고,
"출처를 알 수 없는 앱" 설치를 한 번 허용해 주어야 합니다.

첫 빌드는 IL2CPP 가 C++ 를 통째로 컴파일하느라 오래 걸립니다.
두 번째부터는 캐시가 남아 훨씬 빠릅니다.

## 화면 확인

**Tools > JumpJump > Capture Preview PNG** 를 실행하면 플레이 모드에 들어가지 않고
`<프로젝트루트>/JumpJump_Preview/` 에 시작 화면 / 플레이 중 / 높은 구간 3장이 저장됩니다.
아트를 교체한 뒤 정렬이 맞는지 빠르게 볼 때 쓰세요.

## 높이별 배경

배경은 **높이에 따라 3장이 서서히 갈아탑니다.** 구간 경계 앞 30m 에 걸쳐 겹쳐 넘어가므로
딱 끊기지 않습니다.

| 그림 | 구간 | 내용 |
| --- | --- | --- |
| `BG_01.png` | 0m ~ | 평야 하늘 + 구름 |
