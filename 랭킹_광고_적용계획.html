랭킹과 광고 붙이기

심심할 때 하는 게임 · 2026-09-09 · 방법과 순서 · 결정됨: 플레이스토어 + 원스토어 출시 / 랭킹은 Firebase

한 줄 요약

먼저 정할 것은 두 가지, 만드는 순서는 "네트워크 없이 되는 것부터"입니다. 랭킹과 광고는 둘 다 바깥 서비스에 기대는 일이라, 지금처럼 배치 모드로 검증하는 방식이 통하지 않습니다. 그래서 게임 쪽 뼈대를 먼저 만들어 두고, 바깥 서비스는 나중에 갈아 끼우는 순서를 권합니다.

1단계 게임 안 뼈대 (네트워크 없음 · 지금 방식대로 배치 검증 가능) <-- 여기부터 2단계 랭킹 서버 붙이기 (Firebase) 3단계 광고 붙이기 (AdMob · 처음에는 테스트 광고만) 4단계 스토어 · 정책 (릴리스 서명 / 개인정보처리방침 / 동의 화면) 5단계 폰에서 실기 확인 (배치 모드로는 확인 불가)

스토어에 올리기로 하셨으므로 광고가 실제로 수익이 되는 길이 열렸습니다. 아래 "두 스토어에 올릴 때" 절을 새로 넣었습니다.

왜 Firebase 가 가장 쉬운가

"제반 지식이 없다"고 하셨으니 이유를 적어 둡니다. Firebase 는 서버를 만들지 않고 서버를 쓰는 물건입니다.

  • 서버 컴퓨터를 빌리거나 돌보지 않습니다. 웹 화면에서 몇 번 누르면 저장소가 생깁니다.
  • 로그인을 직접 만들지 않습니다. "익명 로그인"을 켜면 앱이 알아서 사람마다 다른 번호(UID)를 받아 옵니다. 이것이 곧 PID 입니다. 사용자는 아무것도 하지 않습니다.
  • 점수를 넣고 빼는 코드가 몇 줄입니다. "이 자리에 이 값을 써라", "점수 높은 순으로 100개 가져와라" 두 가지면 랭킹이 됩니다.
  • 무료 한도가 넉넉합니다. 개인 게임 규모에서는 돈이 들지 않습니다. 카드 등록도 필요 없습니다.
  • 구글 계정 하나로 시작하고, 나중에 그만두더라도 랭킹만 떼어내면 게임은 그대로 돕니다.

어려운 부분은 코드가 아니라 한 번뿐인 준비 과정(프로젝트 만들기 → 앱 등록 → 설정 파일 넣기 → SDK 임포트)입니다. 그 과정은 제가 화면 순서대로 짚어 드리겠습니다. 사용자께서 직접 하셔야 하는 부분(구글 계정으로 로그인해서 누르는 일)만 하시면 됩니다.

먼저 정할 것 두 가지 결정 완료

① 구글 플레이에 올릴 생각이 있으신가요?

광고는 사실상 여기에 달려 있습니다. AdMob 은 정책상 승인된 스토어로 배포된 앱에만 실제 광고를 내보냅니다. 지금처럼 APK 를 폰에 직접 넣는(사이드로드) 방식으로는 테스트 광고까지만 붙일 수 있습니다. — 붙는 것을 확인하고 화면을 만들어 두는 데는 충분하지만, 수익은 나지 않습니다.

  • 올릴 생각이 있다 → 3단계까지 지금 다 만들고, 스토어 등록 후 광고 ID 만 실제 것으로 바꾸면 됩니다.
  • 당분간 없다 → 광고는 "자리와 흐름"만 만들어 두고(테스트 광고), 실제 노출은 미룹니다. 랭킹은 스토어와 상관없이 지금 바로 됩니다.

참고로 구글 플레이 개발자 등록은 1회 25달러이고, 새로 만드는 개인 계정에는 비공개 테스트(테스터 여러 명 · 일정 기간) 요건이 붙습니다. 이 규정은 자주 바뀌니 가입할 때 화면에 나오는 조건을 확인하셔야 합니다.

"고유 PID" 를 무엇으로 할 것인가

플레이어를 알아보는 값입니다. 후보가 셋인데 성격이 다릅니다.

방법앱을 지웠다 깔면폰을 바꾸면비고
앱이 처음 켜질 때 만든 임의의 번호(GUID)를 폰에 저장 사라짐사라짐가장 간단. 로그인 없음
Firebase 익명 로그인 UID 추천 사라짐사라짐 서버가 발급. 나중에 구글 로그인으로 승격시키면 그때부터 유지됨
구글 계정 로그인 유지유지로그인 화면을 거쳐야 함

권하는 방식: 익명 UID 를 PID 로 쓰고, 화면에 보이는 이름은 별명을 따로 받습니다. PID 는 사람이 볼 값이 아닙니다(길고 의미 없는 문자열). 랭킹표에는 별명이 나옵니다.

안드로이드 광고 ID·기기 고유번호를 PID 로 쓰지 마세요. 구글 정책상 그런 식별자를 다른 용도로 쓰면 안 되고, 스토어 심사에서 문제가 됩니다.

랭킹표를 어떻게 담을까

게임이 두 개(점프점프 · 활쏘기)이고 앞으로 더 늘어나므로, 게임마다 표를 따로 둡니다. 한 사람당 최고 점수 한 줄만 남기면 표가 커지지 않습니다.

ranks / jump    / scores / {PID}  ->  { nick: "홍길동", score: 47900, at: 2026-09-09 }
ranks / archery / scores / {PID}  ->  { nick: "홍길동", score: 320,   at: 2026-09-09 }
  • 게임이 끝났을 때 지금까지의 최고 점수보다 높을 때만 덮어씁니다.
  • 보여줄 때는 점수 내림차순 상위 100명 + "내 순위" 한 줄.
  • 보안 규칙으로 "자기 PID 자리에만 쓸 수 있다" 를 걸어 둡니다.

먼저 선을 그어 둡시다 — 점수 조작은 완벽히 막을 수 없습니다. 점수를 계산하는 곳이 폰 안이라, 마음먹은 사람은 거짓 점수를 올릴 수 있습니다. 제대로 막으려면 서버에서 게임을 다시 굴려 봐야 하는데 규모에 비해 과합니다. 지금은 감수하고, 나중에 문제가 되면 "말도 안 되는 점수 거르기"(상한선) 정도를 붙이는 쪽을 권합니다.

만드는 순서

1

게임 안 뼈대 — 네트워크 없이 (반나절)

바깥 서비스 없이 지금 방식대로 배치 모드로 검증되는 부분을 전부 먼저 만듭니다. 나중에 Firebase/AdMob 은 이 자리에 끼워 넣기만 합니다.

  • PlayerId — PID 만들고 저장
  • PlayCounter — 판 수 세기. 2판마다 신호. 폰에 저장해서 앱을 껐다 켜도 이어짐
  • IRankingService / IAdService — 겉모양(인터페이스)만 정의하고, 지금은 폰 안에만 저장하는 가짜 구현을 씁니다
  • 랭킹 팝업 화면 — 가짜 데이터 10줄로 먼저 그려 봅니다
  • 별명 입력 화면 — 처음 등록할 때 한 번
  • 문구는 전부 strings.csv 에 추가

이 단계가 끝나면 화면과 흐름이 전부 완성됩니다. 바깥 서비스는 아직 하나도 안 붙었는데도요. 여기서 자리·크기·순서를 확정하는 편이 훨씬 편합니다.

2

랭킹 붙이기 — Firebase (하루)

  1. Firebase 프로젝트 만들기 (구글 계정 하나면 됩니다)
  2. 안드로이드 앱 등록 — 패키지 이름 com.zkfpf.jumpjump, 서명 지문(SHA-1) 등록
  3. 내려받은 google-services.json 을 프로젝트에 넣기
  4. Firebase Unity SDK 에서 Auth 와 Firestore 두 개만 임포트
  5. 익명 로그인 → 받은 UID 를 PID 로 사용
  6. 1단계에서 만든 가짜 구현을 진짜 구현으로 교체 (게임 코드는 안 건드림)
  7. 보안 규칙 걸기 — 읽기는 누구나, 쓰기는 자기 자리만

인터넷이 안 되어도 게임은 그대로 돌아가야 합니다. 랭킹 등록에 실패하면 조용히 넘어가고 (로컬 최고 점수는 이미 저장되고 있습니다), 랭킹 화면에서만 "불러오지 못했습니다"를 보여줍니다.

3

광고 붙이기 — AdMob (하루)

  1. AdMob 계정 만들고 앱 등록 → 전면 광고(Interstitial) 광고 단위 만들기
  2. Google Mobile Ads Unity 플러그인 임포트, 앱 ID 설정 (안드로이드 최소 API 레벨을 올려야 할 수 있습니다 — 플러그인 문서 확인)
  3. 개발 중에는 반드시 구글이 주는 테스트 광고 ID 를 씁니다
  4. 2판마다 노출되도록 1단계의 신호에 연결
  5. 유럽 대상 동의 화면(UMP) 붙이기 — 앱 시작할 때 한 번
  6. 어린이 대상 여부 / 광고 콘텐츠 등급 설정

내 광고를 내가 누르면 안 됩니다. 계정이 정지되고 되돌리기 어렵습니다. 확인은 반드시 테스트 광고로 하세요. 실제 ID 로 바꾸는 것은 스토어에 올리는 시점입니다.

4

스토어 · 정책 (스토어에 올릴 때만)

  • 릴리스 키스토어를 만들고 절대 잃어버리지 않기. 잃어버리면 같은 앱을 갱신할 수 없습니다. 지금은 Unity 디버그 키로 서명되고 있어서 이대로는 못 올립니다. 바꿀 곳은 JumpJumpBuild.cs 의 useCustomKeystore 와 buildAppBundle 입니다 (CLAUDE.md 에 적어 둔 그 자리입니다).
  • 개인정보처리방침 URL — 광고와 식별자를 쓰므로 필수입니다. 웹에 한 장 올려야 합니다.
  • 데이터 세이프티 양식 작성 (무엇을 수집하는지 신고)
  • 패키지 이름은 바꾸지 않습니다 — 바꾸면 기존 설치본과 다른 앱이 됩니다.
5

폰에서 실기 확인

이 두 기능은 배치 모드로 검증할 수 없습니다. 지금까지처럼 제가 자동으로 확인해 드릴 수 없는 첫 작업입니다. 그래서 폰에서 확인할 목록을 따로 만들어 드리겠습니다.

  • 비행기 모드로 게임 한 판 — 안 멈추고 그대로 끝나는가
  • 2판째에 광고가 뜨는가 / 광고를 닫으면 원래 자리로 돌아오는가
  • 광고 도중 뒤로 버튼을 눌러도 이상해지지 않는가
  • 앱을 껐다 켜도 판 수가 이어지는가
  • 랭킹에 내 점수가 올라가고 순위가 맞는가

광고를 "어디서" 띄울 것인가

기술보다 이쪽이 더 중요합니다. 잘못 놓으면 정책 위반이거나, 사용자가 앱을 지웁니다.

게임 오버 화면이 뜬다 | +-- 점수를 본다 (여기서 광고 띄우면 안 됨) | +-- [다시하기] 또는 [로비로] 를 누른다 | +-- 2판째라면 -> 전면 광고 -> 끝나면 원래 가려던 곳으로 <-- 여기
  • 게임 도중에는 절대 안 됩니다. 점프하려고 누른 손가락이 광고를 누르면 정책 위반입니다.
  • 게임 오버가 뜨자마자도 좋지 않습니다. 점수를 볼 틈은 주고, 다음 화면으로 넘어가는 길목에 둡니다.
  • 광고와 랭킹 팝업이 겹치지 않게 합니다. 순서: 점수 → (랭킹 등록) → 다음으로 이동할 때 광고.
  • 광고는 미리 불러 둡니다. 띄울 때 불러오면 몇 초 멈춰 보입니다. 아직 안 불러졌으면 광고를 건너뛰고 그냥 넘어갑니다 — 게임이 막히면 안 됩니다.
  • 2판마다라 해도 너무 자주 뜨지 않게 최소 간격(예: 3분)을 같이 두는 편이 좋습니다.

이 프로젝트에서 손댈 곳

지금 구조를 그대로 지키면서 붙일 수 있습니다. 게임 두 개의 코드는 각각 한 줄씩만 늘어납니다.

파일무엇
Shell/Scripts/PlayerId.cs 새로PID 만들고 저장
Shell/Scripts/PlayCounter.cs 새로판 수 세기 · 2판마다 신호
Shell/Scripts/Ranking/*.cs 새로랭킹 (겉모양 + 가짜 + Firebase)
Shell/Scripts/Ads/*.cs 새로광고 (겉모양 + 없음 + AdMob)
JumpJump/Scripts/GameManager.csEndRun 끝에 "한 판 끝났다" 알리는 한 줄
Archery/Scripts/ArcheryGame.cs똑같이 한 줄
Shell/Editor/ShellSceneBuilder.cs랭킹 팝업 만드는 함수 (지금 MakeExitToLobbyUI 가 있는 자리 옆)
strings.csv새 문구 (랭킹 / 별명 / 등록 실패 등)

지켜야 할 규칙 하나. Step(dt, tap) 안에서는 광고도 네트워크도 부르지 않습니다. EndRun 은 "끝났다"는 사실만 남기고, 실제 광고 띄우기와 점수 보내기는 그 바깥에서 합니다. 그래야 지금의 자동 플레이테스트가 계속 돕니다 — 봇이 120초 동안 수십 판을 도는데 거기서 광고를 부르면 검증 자체가 망가집니다.

미리 알아 둘 걸림돌

  • APK 가 커지고 빌드가 느려집니다. Firebase + AdMob 은 구글 라이브러리를 여럿 끌고 옵니다. 지금 47MB 인데 60MB 를 넘길 수 있습니다. (스토어에 올릴 때 쓰는 AAB 형식이면 실제 내려받는 크기는 줄어듭니다)
  • SDK 를 넣은 뒤 빌드가 한 번은 깨질 가능성이 높습니다. 라이브러리 버전 충돌은 흔한 일이라, 그 자리에서 맞춰 나가야 합니다. 하루치로 잡아 두는 게 마음이 편합니다.
  • 인터넷 권한이 들어가므로 스토어 신고 내용이 달라집니다.
  • 별명에는 길이 제한과 욕설 걸러내기가 필요합니다. 남들에게 보이는 글자입니다.
  • 랭킹은 사람이 없으면 비어 보입니다. 처음에는 "이번 주 상위 10명"처럼 범위를 좁게 잡는 편이 덜 허전합니다.

두 스토어에 올릴 때 (플레이스토어 + 원스토어)

앱은 하나입니다. 스토어만 둘입니다. 같은 코드, 같은 패키지 이름 (com.zkfpf.jumpjump)으로 양쪽에 올립니다. 갈리는 곳은 세 가지뿐입니다.

항목구글 플레이원스토어

키스토어 파일과 비밀번호를 잃어버리면 안 됩니다. 지금은 Unity 디버그 키로 서명되고 있어서 이대로는 어느 스토어에도 못 올립니다. 릴리스 키스토어를 하나 만들고, 파일과 비밀번호를 안전한 곳에 두 벌 보관하세요. 잃어버리면 원스토어 쪽은 같은 앱을 갱신할 수 없게 됩니다. (플레이는 Play 앱 서명을 쓰면 업로드 키 재발급이 가능합니다)

빌드 스크립트에서 할 일

JumpJumpBuild.cs 에 이미 useCustomKeystore 와 buildAppBundle 이 꺼진 채로 들어 있습니다. 여기에 "플레이용(AAB) / 원스토어용(APK)" 두 가지로 굽는 메뉴를 붙이면 끝입니다. 버전 번호(versionCode)는 양쪽 같은 값을 쓰고, 올릴 때마다 하나씩 올립니다.

Firebase 는 스토어와 상관없습니다

익명 로그인 + Firestore 만 쓰면 서명 지문(SHA-1) 등록이 필요 없습니다. 그래서 원스토어로 받은 앱에서도 랭킹이 똑같이 동작합니다. (구글 로그인이나 Play Games 를 붙이면 그때는 지문 등록이 필요합니다 — 지금은 안 씁니다)

광고는 확인이 하나 필요합니다

AdMob 은 승인된 스토어로 배포된 앱에만 실제 광고를 내보냅니다. 플레이스토어는 확실합니다. 원스토어가 그 목록에 포함되는지는 AdMob 정책 페이지에서 확인해야 합니다 — 제가 단정할 수 없는 부분이고, 정책은 바뀝니다. 다만 어차피 플레이스토어에 올리시므로 광고 자체는 문제가 없습니다. 확인 결과에 따라 원스토어 배포본에서만 광고를 끄는 것도 가능합니다(빌드 때 스위치 하나).

결제(인앱 구매)는 이야기가 다릅니다

결제를 넣으면 스토어마다 결제 모듈이 달라 빌드를 둘로 나눠야 합니다. 지금은 결제가 없고 광고만이므로 해당되지 않습니다. 나중에 "광고 제거" 같은 상품을 팔 생각이시면 그때 다시 이야기하는 편이 좋습니다.

정해진 것 (추가)

  • 별명은 앱 전체에서 하나뿐입니다. 경쟁심을 유도하기 위한 결정입니다. 남이 쓰는 별명이면 다시 받습니다. 진짜 중복 검사는 2단계에서 Firestore 트랜잭션으로 붙입니다 — "빈자리 확인"과 "내 것으로 표시"를 한 번에 처리해야 두 사람이 동시에 같은 별명을 잡는 일이 없습니다.
  • 랭킹은 로비의 아이콘으로 엽니다. 게임 오버 화면이 아니라 별도 창입니다.

남은 작은 질문

1단계를 진행하면서 정하면 되는 것들입니다. 답을 기다리지 않고 시작할 수 있습니다.

  1. 별명을 나중에 바꿀 수 있게 할까요? 하나뿐인 이름이라 바꾸려면 쓰던 별명을 놓아 주고 새 별명을 잡는 절차가 필요합니다. 지금은 한 번 정하면 그대로입니다.
  2. 욕설·비속어를 걸러낼까요? 남들에게 보이는 이름이라 스토어 심사에서도 볼 수 있는 부분입니다. 금지어 목록을 CSV 로 두면 사용자께서 직접 채우실 수 있습니다.
  3. 화면 문구를 한글로 통일할까요? 랭킹·별명 창은 한글로 넣었는데 (버튼 그림이 한글이라 맞췄습니다), 게임 안 HUD 는 아직 영어입니다. strings.csv 만 고치면 되고 코드는 건드리지 않습니다.

지금 하는 일

1단계(게임 안 뼈대)를 시작합니다. 바깥 서비스 없이 되는 부분이라 지금까지처럼 배치 모드로 검증하면서 만들 수 있습니다. 2단계(Firebase)로 넘어갈 때 사용자께서 웹에서 하셔야 하는 일을 화면 순서대로 정리해 드리겠습니다.
